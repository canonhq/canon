# Spec View Page Redesign

Replace the monolithic server-rendered HTML blob with structured Vue components that mirror the editor's card-based visual language, making spec reading as pleasant as spec editing.

## 1. Background

<!-- specwright:system:1 status:done -->

The spec view page (`/app/:org/specs/...`) currently renders specs as a flat HTML dump generated by `render.py` on the backend, injected via `v-html`. This produces a wall of text with minimal visual hierarchy — gray left borders, plain checkboxes, and no way to navigate or collapse sections.

Meanwhile, the structured editor uses card-based section components with accent borders, collapsible bodies, progress bars, and clear visual grouping. Users already prefer this visual language. The view page should adopt the same design patterns in a read-only context.

### Current architecture (being replaced)

1. Backend `render_spec_html()` converts `SpecDocument` → HTML string
2. `SpecContent.vue` injects HTML via `v-html` + DOMPurify
3. No interactivity, no collapsibility, no progress visualization

### Target architecture

1. API already returns structured `SpecDocument` JSON (sections, ACs, frontmatter)
2. New Vue components render sections as read-only cards
3. `rendered_html` field becomes unused for web view (kept for email/export)

## 2. Spec Summary Header

<!-- canon:system:2 status:in_progress -->

Replace the current `SpecHeader.vue` metadata strip with a richer summary panel.

### Acceptance Criteria

- [ ] Display total section count, AC count, and coverage percentage
- [ ] Show a horizontal progress bar with coverage fill (emerald at 100%, brand color otherwise)
- [ ] Display owner, team, tags, created/updated dates in a compact metadata row
- [ ] Keep Edit and View on GitHub action buttons
- [ ] Show review status badge alongside spec status badge

## 3. Section Cards

<!-- canon:system:3 status:in_progress -->

Render each spec section as a read-only card matching the editor's `SectionCard` visual style.

### Acceptance Criteria

- [ ] Each section renders in a rounded card with 3px left accent border
- [ ] Section header shows section number, title, status badge, and AC summary (e.g. "5/8 ACs")
- [ ] Sections are collapsible — click header to toggle body visibility
- [ ] Done sections start collapsed by default; in_progress/todo/draft start expanded
- [ ] Nested child sections render indented within their parent card
- [ ] Prose content renders as formatted markdown (not raw text)
- [ ] Ticket links render as styled pill badges (Jira/Linear/GitHub)
- [ ] Delta badges (added/modified/removed) display when present

## 4. AC Progress Bars

<!-- canon:system:4 status:done -->

Each section card shows a visual progress indicator for its acceptance criteria.

### Acceptance Criteria

- [ ] Progress bar shows checked/total ratio as a colored fill
- [ ] Bar uses emerald when 100%, brand-500 otherwise
- [ ] Numeric count displayed next to bar (e.g. "5/8")
- [ ] Individual ACs render as styled checkbox list with strikethrough on checked items
- [ ] Realized-in references show as purple PR link badges on checked ACs

## 5. Collapsible Sections

<!-- canon:system:5 status:done -->

Support collapse/expand for managing large specs.

### Acceptance Criteria

- [ ] Each section has a chevron toggle in the header
- [ ] Collapse animation matches the editor (smooth max-height/opacity transition)
- [ ] "Expand All" / "Collapse All" controls in the spec header area
- [ ] Collapse state is local (not persisted across page loads)
- [ ] Collapsed sections show status badge + AC summary inline in header

## 6. Table of Contents Sidebar

Sticky sidebar for navigating large specs. Lower priority — implement if time permits.

### Acceptance Criteria

- [ ] Sticky left sidebar listing section titles with status dots
- [ ] Clicking a section title scrolls to that section

## 7. Implementation Notes

<!-- canon:system:7 status:done -->

### New components
- `SpecSectionCard.vue` — read-only section card (mirrors editor `SectionCard` styling)
- `SpecSummary.vue` — coverage bar + metadata summary
- `SpecAcceptanceCriteria.vue` — read-only AC list with progress bar

### Modified components
- `SpecDetail.vue` — use new structured components instead of `SpecContent`
- `SpecHeader.vue` — integrate summary metrics
- `SpecView.vue` — optional sidebar layout

### Removed/deprecated
- `SpecContent.vue` — no longer used for web view (keep for potential reuse)
- `render.py` — keep for email/webhook/export, but web view no longer calls it

### Markdown rendering
Use `markdown-it` (already used by VitePress in docs site) or render prose server-side per-section and include in the `SpecDocument` response. Prefer client-side to avoid adding backend coupling.
