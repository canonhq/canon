# Changelog Automation

## 1. Background

The docs site at canonhq.co/docs now has an automated changelog page generated from CHANGELOG.md. The private repo's `CHANGELOG.md` is auto-generated by Python Semantic Release from conventional commits, but it's raw and noisy — internal CI chores, repeated PR review round-trip entries (e.g. 5 "address round-N PR feedback" lines for one PR), and cloud-only scopes that aren't relevant to OSS users.

The docs site already has a `gen-refs` pipeline (`docs-site/.vitepress/scripts/`) that auto-generates CLI, MCP, and API reference pages. A changelog generator should plug into this same pattern: read `CHANGELOG.md`, filter and group entries, and output a clean `docs-site/changelog.md` that VitePress renders.

### Two audiences, two framings

| Channel | Audience | What they need |
|---------|----------|----------------|
| Docs site changelog | Users, evaluators, OSS contributors | Feature-level summaries grouped by minor version. Only user-facing changes. No internal CI/test noise. |
| Private `CHANGELOG.md` | Internal devs | Full commit-level detail (already handled by Semantic Release). |

The public `canonhq/canon` repo currently has no CHANGELOG.md and no GitHub Releases. The OSS export script (`export-oss.sh`) does not include the changelog. This spec covers generating the docs-site page; public repo releases are a separate concern for later.

## 3. Design

### Script architecture

```
CHANGELOG.md (repo root)
    │
    ▼
gen-changelog.py
    ├── parse_changelog()     # regex-based parser for semantic-release format
    ├── filter_entries()      # drop ci/test/chore, drop cloud-only scopes
    ├── collapse_duplicates() # dedupe entries sharing same PR number or commit
    ├── group_by_minor()      # v1.26.0 + v1.26.1 → "v1.26"
    ├── rewrite_links()       # canon-private → canon in URLs
    └── render_markdown()     # output VitePress page with frontmatter
```

### Filtering rules

**Exclude** entries where:
- Type is `chore`, `ci`, `style`, or `refactor` (unless scope is user-facing)
- Scope is `test` only
- Commit message matches "address.*PR.*feedback" or "address.*review" pattern
- Scope references cloud-only modules not in OSS export

**Include** entries where:
- Type is `feat`, `fix`, `docs`, or `perf`
- Type is `BREAKING CHANGE`

### Link rewriting

Replace `github.com/canonhq/canon-private` with `github.com/canonhq/canon` in all URLs. PR links may not exist in the public repo — emit commit links only if they're for OSS-exported code, otherwise omit the link.

### Output format

```markdown
---
title: Changelog
---

# Changelog

## v1.26

### Features
- Zitadel authentication provider with device flow support

### Bug Fixes
- Fix ticket sync using single event loop for all specs

## v1.25
...
```
